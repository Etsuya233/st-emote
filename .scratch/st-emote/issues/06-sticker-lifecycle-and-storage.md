# 06 — 存储与生命周期：上传之后的一切

**What to build:** 表情上传之后的全部管理动作，以及图片本身的可靠性：替换、删除、批量删除、外链、格式与体积把关、跨设备后缺图的处理、以及把一整套表情打包搬走。

**Blocked by:** 01 — 闭环：一张表情能在消息里出现

**Status:** ready-for-agent

- [ ] 能替换某张表情的图片，且保留它的标签与描述
- [ ] 能删除单张，也能多选后批量删除；表情包删除有二次确认；删除后对应图片文件立刻消失
- [ ] 能直接粘一个网络图片地址当表情，界面上标注「外链」；外链失效时按未命中处理
- [ ] 上传只接受 `png` / `jpg` / `webp` / `gif`；单文件超过 5MB 被拒并说明原因；上传时给出建议尺寸（高度 ≤ 512px）提示；动图保持动效、不改帧
- [ ] 同一台 ST 服务端的另一台设备上能看到同样的表情；图片文件没同步过来时该包标灰、仍可启用、可点进去重新指定图片
- [ ] 能把一个表情包导出成单个压缩包（内含图片与元数据：标签、描述、图片文件名、投放方式覆盖），也能导入别人给的包
- [ ] 导入时包名已存在则拒绝并提示；导入后默认不启用
- [ ] 一张图片只被一个表情使用，不存在共享引用

# 12 — 表情网格：默认只看图，单个编辑进浮层，批量是一个模式

**What to build:** 表情包列表现在把每张表情的六个控件（勾选框、缩略图、标签、描述、投放方式、替换、删除）全部铺开，十个表情的包就是六十个控件、二十行，面板是一堵控件墙。改成 QQ / 微信 / TG 那样的三层：**表情包手风琴（同时只开一个）→ 固定边长的方格网格（默认只有图 + 标签）→ 点一个格子弹出浮层做单个表情的编辑**。批量删除收进一个「批量」模式开关，默认态下勾选框根本不渲染。

## 背景

截图里的现状：三个表情包全部展开，每个包的头部一行控件、下面「作用域 + 全选」一行，再下面是每张表情两行控件。**冗杂的成因不是控件太大，是编辑态与多选态常驻。**

- `buildStickerElement` 把标签输入框、描述输入框、投放方式下拉、替换、删除**全部默认渲染**，而它们是「点进去才需要」的东西。压缩它们只会得到一个更密的控件墙。
- 「勾选以便批量删除」这个复选框**每一行都常驻**，于是批量删除这种低频动作占掉了每张表情最宝贵的横向空间。
- 缩略图只有 40px，却和两行表单并排，占的全是控件的横向空间。
- 表情包**没有折叠态**：`renderPackList` 一次把所有包都建出来，用户没有「先看一个」的余地。

Line / QQ / 微信 / TG 的面板拆开看是同一件事：**格子是唯一的默认内容；详情是点开才有的；多选是一个模式而不是一种常态。**

## 做什么

### 一、包层：手风琴，同时只开一个

```
库
├─ 搜索框
├─ 新建表情包
└─ 包列表（手风琴，同时只开一个）
   ├─ 包头：封面 包名 数量 徽章 │ 上传 链接 批量 导出 删包 │ chevron
   ├─ 作用域三项
   ├─ （批量态才有）全选 / 已选 n / 删除选中
   └─ 网格：固定边长方格，一行放得下几个放几个
```

- **默认全部收起**，包头只有一行。库空时仍然是上手卡片（票 13 的东西不动）。
- 展开一个包时，其余收起。
- **手风琴不用客户端的 `inline-drawer`**：包头里有 `<input>` 包名和五个动作按钮，客户端的委托点击会在点包名时把抽屉滑开、点上传时也把抽屉滑开。而且客户端的抽屉头有自己的排版（粗体、整行 padding），与这个密集的包头是两回事。所以包头是一个自己的 `div[role=button]`，`aria-expanded` 挂在它身上，客户端那套（`collapsibleSection`）留给设置区里那些**只有一句标题**的说明段——那正是它擅长的形状。
  - **包名输入框与五个动作按钮自己 `stopPropagation`**，所以「点包名改名」与「点头部展开」不冲突。
- 包头同时点开的那一个存**模块级**（`openPackName`），因为 `renderPackList` 每次都把包列表整个重建，状态放 DOM 上活不过一次刷新。

### 二、网格层：固定边长的方格

```css
.st-emote-stickers {
    display: grid;
    grid-template-columns: repeat(auto-fill, minmax(56px, 1fr));
    gap: var(--st-emote-gap);
}
```

**`auto-fill` + 固定 `minmax`，不写死列数。** 面板宽度在 300px 到两倍之间浮动，写死 5 列在窄栏挤爆、在宽栏拉散；固定格子边长 + 一行放得下几个放几个，效果一样稳定而且天然自适应。56px 的格子在 320px 栏里是 4 列，500px 里是 6 列。

单个格子：

```
┌─────────┐
│  图片    │  ← 正方形，object-fit: contain
├─────────┤
│ 标签    │  ← 一行，超出省略，hover 出 title
└─────────┘
```

- **标签常驻格子里**（QQ / 微信都这么做）。标签是标记里写的东西，是用户扫这一片时唯一要找的标识；TG 那种只在 hover 显示的写法在窄面板里不合适。
- **徽章改成角标**，格子里塞不下文字徽章：
  - 外链 → 右上角一个小链接图标（复用已核过的 `fa-link`）
  - 待填标签 → 虚线边框 + 中心一个 `?`（与现有 `.st-emote-thumb-missing` 的虚线语义一致）
  - 批量态选中 → 描边高亮 + 左上角对勾
- 格子是 `div[role=button][tabindex=0]`，`title` 是「标签 — 描述」，Enter / Space 等同点击。

### 三、浮层：点一个格子，编辑这一个表情

`adapter/sticker-editor.js`，`openStickerEditor(context, pack, sticker, refresh, searching)`。

- **自己建 DOM，不走 `callGenericPopup`**：客户端那个弹层只接受 CONFIRM / INPUT / DISPLAY，弹的是纯文本，放不下表单控件（`adapter/dialogs.js` 里已经在用它弹确认与单行输入）。
- 挂在 **`document.body`** 下而不是面板里：`.st-emote-packs` 是 `overflow-y: auto`，挂进去会被裁掉。
- 内容就是原来那两行：标签、描述、投放方式、替换、删除。
- 打开时标签输入框自动聚焦；Esc 与点遮罩都关闭；关闭后焦点回到刚才点的那个格子（按 `data-sticker-id` 找回，重建过也找得到）。
- 搜索态下不给删除按钮，沿用「搜索时隐藏删除」的既有规矩。
- **浮层不参与手风琴**：收起一个包不会关掉正在编辑的表情——用户可能正在描述输入框里打字。

### 四、批量：每包一个模式开关

- **默认态**：格子可点开浮层；`selectedStickerIds` 那套勾选框**完全不渲染**，`.st-emote-selection` 那一行也不出现。
- **批量态**：格子变成勾选（点格子 = 勾选，不再弹浮层），出现 `全选 / 已选 n / 删除选中`。
- 开关在包头，**每个包一个**（不是全局）：`handleBatchDelete` 本来就是按包取的，`selectedStickerIds` 虽是全局的但计数是按包的，跨包多选会让「已选 12」到底删哪 12 个变模糊。
- 搜索态下那两条既有规则（`selectMatches` / `searchDeleteHint`）照旧，只是它们现在只存在于批量态里。

### 五、状态放哪

模块级三个，与既有的 `selectedStickerIds` 同理——包列表每次 `refresh()` 都整体重建，放 DOM 上的活不过一次刷新：

| 名字 | 含义 |
| --- | --- |
| `selectedStickerIds` | 既有：批量勾选，跨刷新与跨挂载保留 |
| `openPackName` | 手风琴当前展开的包；`null` 是全部收起 |
| `batchPackName` | 当前处于批量态的包；`null` 是没有 |

`revealPack` 之后补一个 `revealSticker`：新建包之后定位到包头并**展开它**；上传完图片之后定位到那一张新格子。

## 手动验收项

- 56px 的格子在 300px 栏与 600px 栏里各是几列，标签截断后还能不能认出来
- 角标（外链 / 待填标签）在深色与浅色主题下读不读得出
- 手风琴：点头部空白处能展开、点包名不会误展开、点上传不会误收起
- 浮层：Esc、点遮罩、关闭按钮三条路都能关；关掉之后焦点回到原来那一格
- 浮层在**窄面板**里会不会超出右边（遮罩是 fixed，卡片要 max-width）
- 上传完新图片，那一格是否自己滚进视野
- 批量态下点格子不弹浮层，退出去之后格子恢复可点

## 已知取舍

- **浮层的控件在 DOM 里只有一份。** 一个包有 30 张表情时，用户只能一次编辑一张。这是「默认态只放图」换来的，编辑本来就是低频动作。
- **手风琴不用客户端的抽屉**，因此**没有客户端的滑开动画**，展开是瞬间的。理由写在「做什么」第一节：客户端的委托点击会跟包名输入框和五个动作按钮打架。用 `setExpanded` 那套动画的收益不值得这个冲突。
- **`openPackName` / `batchPackName` 不持久化**：刷新页面回到「全部收起、没有批量态」。与既有的折叠状态不持久化是同一条理由（票 11 的注释：持久化要决定存哪、怎么与票 08 的 `settings` 合并，是单独的票）。
- **格子里不放投放方式状态。** 一个表情单独覆盖了投放方式，格子上看不出来——要点进浮层。格子那一行的空间只够图和标签。

### 实际做了什么

见下方各提交。

### 与票据不同的两处

- **`auto-fill` 而不是写死的列数**，票据里已经这么写了，实现照办；这里只记一句**为什么**：`auto-fill` 在 320px 栏里给出 4 列、500px 里给出 6 列，而任何写死的数字在其中一端都是错的。
- **`openPackName` / `batchPackName` / `selectedStickerIds` 三份状态在挂载时清空**。原先 `selectedStickerIds` 是**跨挂载保留**的（票 10 的理由是「一个真实用户的勾选应当活过一次重绘」），而实测下来跨挂载保留带来的是另一件事：一个测试挂载面板时看到上一次测试勾过的格子，于是「点一下勾上」实际是在取消勾选。挂载对客户端来说就是一次页面加载（切语言时它自己会刷新），所以**活过重绘、活不过挂载**是更准确的说法，三份状态一起改掉，`selectedStickerIds` 的注释同步改了。

### 快照为什么是两张

票据里写的是「快照的采集状态要写清楚：普通挂载 + 展开一个包 + 打开一个浮层，三个条件缺一个就少一半控件」。写的时候以为那是一个状态，实际**批量态与浮层互斥**——批量态里点格子是勾选，不是打开浮层，一个格子只有一个点击。于是分成两张表：`EXPECTED_CONTROL_SURFACE` 在「开一个包、开批量、勾两个」下录，`EXPECTED_EDITOR_SURFACE` 在「开一个包、点一个格子」下录。两张表的采集状态都写在各自的注释里，比一张拼起来的表更接近「用户真能看到的某个面板」。

### 控件清单那一段的实际 diff

- 没了：每个表情一行的标签、描述、投放方式、替换、删除（`pack "…" / sticker "…"` 整段消失）。
- 多了：每包一个 `st-emote-batch`，以及 `pack "…" / selection bar` 那一行。
- 变了：一个关着的包现在只贡献它自己的包名输入框那一行；`controlRegion` 新增了 `/ actions` 这一档（动作按钮原先混在 `/ header` 里）。
- 没变：包名输入框、三个作用域勾选、上传 / 加链接 / 导出 / 删包、调试区、四个设置块、两套尺寸集，以及浮层里那五个控件的 tag / 类名 / 说明文字 / select 选项。

### 浮层画在了抽屉底下（截图里那三处「样式很奇怪」）

票据说浮层挂在 `document.body` 下是对的（面板住在客户端那个会裁、会滚的 `.drawer-content` 里），但**挂到 body 下还带出一个后果，票据没写**：`#top-settings-holder` 是 body 的直接子元素，`position: relative; z-index: 3005`，抽屉打开时 4005——而浮层与它在**根层叠上下文**里竞争。而浮层原本写的是最常写的那一档 `z-index: 1000`，于是它**画在召唤它的那个抽屉底下**，隔着那层半透明带模糊的背景看出去：整张卡片发灰、发虚，**看着像样式坏了，不像窗口放错了**。改成 10000（客户自己浮层的档位，`#dialogue_popup` 一类在 9999）。

顺着截图里另外两处也一并改了，三处都是同一个来源——**面板上写的尺寸/配色规则在浮层这个上下文里不成立**：

- **投放方式下拉是一个 9em 高的方块。** `.st-emote-sticker-placement { flex: 0 1 9em }` 是给面板上那一行写的（basis 在行里是宽度），浮层的 body 是**列**，basis 在列里就是高度。加一条 `.st-emote-editor-body .st-emote-sticker-placement { flex: 0 0 auto; width: 100% }`。
- **卡片拿自己的字色当底色。** ST 的 `body` 是 `color: var(--SmartThemeBodyColor)`，而卡片原来是 `background: var(--SmartThemeBodyColor)`：浮层里所有没有自己配色的字（标题、角标）在任何主题下都**与自己的底色同色**。改成客户自己的面 + 字配对（`--SmartThemeBlurTintColor` 底 / `--SmartThemeBodyColor` 字），与 `.drawer-content` / `.popup` 同一套。
- **两档间距在浮层里是死的。** `--st-emote-gap` / `--st-emote-space` 原来声明在 `#st_emote_drawer` 上，浮层不在那个抽屉里，`gap: var(--st-emote-gap)` 算成 `normal`（0），字段之间的间距实际来自客户 `.text_pole` 自带的 `margin: 5px 0`。两个变量上提到 `body`，面板与浮层从此说同一个数字。

这四条由 `tests/panel.test.js` 的「the editor is a surface of its own, above the drawer that opened it」钉住：jsdom 与 DOM 都看不见它们，只有读 `style.css` 查得到，而删掉其中任何一条都不会让任何别的测试变红。

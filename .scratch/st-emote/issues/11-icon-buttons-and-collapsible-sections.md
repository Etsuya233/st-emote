# 11 — 面板交互：图标化按钮，可折叠的区块

**What to build:** 面板里那一排排写着字的按钮换成内置图标；那些一打开就占半屏的区块（两套尺寸集、宏说明、正则、导入导出、试渲染）改成可折叠、默认收起。不改任何设置项、不改任何行为、不改任何句子的**意思**。

**Blocked by:** 10 — 面板观感：让它在窄栏里也站得住

**Status:** ready-for-agent

> **串行执行。** 票 12（表情网格）也要重写 `tests/panel.test.js` 里那条控件清单快照,和本票正面冲突。两张票在**同一个 worktree、同一条分支上依次做**,不要并行开 worktree。

## 一、按钮图标化

### 背景

截图里一排「Upload images / Add image URL / Export .zip / Delete pack」全是有字的按钮,占了三行竖直空间,却只传达四个动作。Font Awesome 已经在用了——`panelSkeleton()` 里就有 `fa-solid fa-circle-chevron-down`,客户自带字体,运行时不新增依赖。

### 做什么

- **动作按钮改成只有图标**,本地化的句子移进 `title` 与 `aria-label`。**i18n 目录里的键一个字都不删**,它们从按钮文字变成了 tooltip,仍然是双语。
- **哪些改成图标**:上传图片、加外链、导出 zip、删除表情包、替换表情图、删除表情、创建包、导入包、复制正则、试渲染、重新渲染、批量删除、创建缺失的表情包。
- **哪些保持文字**:所有**说明性标签**——下拉框的标题、尺寸字段的名字、复选框的说明、那一大段提示文字、以及「HTML tag form:」这种冒号前缀。这些是标签不是动作,图标化只会让用户看不懂。
- 图标名的映射表放在 `adapter/ui.js` 里,照抄现有 `PLACEMENT_LABEL_KEYS`（在 `sizing-panel.js`）与 `PACK_STATE_LABEL_KEYS` 的写法:**一张语义名 → 类名的表,不是散落各处的字符串**。
- `actionButton()` 的签名跟着改成接图标加标签,`filePickerButton()` 同样。
- 图标要有**尺寸与对齐**的统一规则（`style.css` 里一条 `.st-emote-button` 族）,不能每个按钮各写各的字号。

### 可发现性

图标化是**有代价的**:文字按钮自带标签,图标没有。三个必须做的补偿——

1. `title`（悬停提示,双语）
2. `aria-label`（读屏）
3. 面板顶部的「这段操作是什么」那一句提示里,说明按钮是图标且悬停有说明

**如果实机验证发现某个动作图标化后明显更难找**,那个按钮可以保留文字——但要在 Comments 里写明是哪一个、为什么。

### 图标不存在怎么办

FA 的图标是按名字查的,**查不到就是空白,没有报错**。所以:

- 图标名要挑 FA6 免费版确定有的,别用 Pro 独有的（`fa-file-zipper` 这类拿不准的先查一遍）
- 加一条**孤儿键测试**:图标映射表里的每一项都必须有人用,就像目录的孤儿键测试那样。这样删按钮时不会留下一个查不到名字的图标

### 手动验收项

- 每个图标都真的渲染出来了,**没有一个是空白**（这一条自动化测不了,只能看）
- 悬停提示在深色/浅色主题下都读得清
- 读屏能念出每个动作（`aria-label` 生效）

## 二、区块可折叠

### 用客户自己的模式,不要自造

`panelSkeleton()` 已经在用 SillyTavern 的 `inline-drawer-toggle` + `inline-drawer-content` + `inline-drawer-icon fa-solid fa-circle-chevron-down down`。**折叠块也用同一套**——客户自己的动画、样式与 `aria-expanded` 行为都白拿,面板看起来也是原生的。自造一套 `<details>` 或手写 max-height 动画是在重复发明一个我们已经用着的东西。

### 折叠哪些

| 区块 | 默认 | 理由 |
| --- | --- | --- |
| 两套**尺寸集**（`inline` / `block` 各一组 7 个字段） | **收起** | 一次 14 个输入框,是面板最大的一块。绝大多数用户不调 |
| **宏**说明 + 示例 | 收起 | 一段说明加一整块 `<pre>`,没有设置 |
| **正则**说明 + 示例 + 复制按钮 | 收起 | 同上 |
| **导入导出**说明 + 导入行 | 收起 | 偶尔用一次的操作 |
| **试渲染**（调试区） | 收起 | 是个工具,不是设置 |
| **处理**组（总开关 + 两个形态开关 + 用户消息） | **展开** | 这些是主开关,折叠起来等于藏起来 |
| **标记**组（标签名） | 展开 | 一个输入框,不值得折 |
| **投放方式** | 展开 | 一个下拉框 |

「外观」组里的尺寸集单独折,组本身不折——一个组折起来、组里两个子块各折一层,三层套娃比不折还难找。

### 折叠**不能藏住错误**（这条最容易漏）

非法尺寸值会在输入框旁边显示提示、在控制台记一行。**如果那一组是收起的,用户永远看不到那个提示。** 所以:

- 一个尺寸集里**有非法值时,自动展开**它,并保持展开直到那个值被改对或被清空
- 这条要有测试:存一个非法值 → 面板挂载 → 那一组是展开的;把值改合法 → 下一��重新渲染时它可以收回
- 同理,总开关关掉时那半句「宏也不展开」的提示不能被折叠挡住（它本来就在展开的组里,但要确认）

### 状态不持久化

折叠状态**只活在这次挂载里,刷新页面回到默认**。不要为此建一套持久化机制——没有人要求它,而持久化就要决定「存哪、怎么合并、和票 08 的 `settings` 什么关系」,那是一件单独的票。

有一个例外要注意:面板里**包列表**每次改动都会整体重建（`refresh()`）,但**设置区不会**。所以设置区的折叠状态天然能在编辑过程中保持,不需要额外做什么;而包列表那一侧的状态(见票 12)是另一回事,不要在这里顺手建。

### 手动验收项

- 折叠块的展开/收起动画与客户自己的抽屉一致
- 键盘可达:`tab` 能走到折叠头、`enter`/`space` 能展开、`aria-expanded` 正确
- 一个非法尺寸值在收起状态下被发现时,那一组是否真的自动展开了（这条有测试,但观感要人看）
- 收起的尺寸集,它的标题上**看得出里面被改过**吗（没改过的两套看起来一样,改过的应该认得出来）——如果做不了,在 Comments 里说明

## 三、不能做的事

- **不新增、不删除、不重命名任何设置项、按钮或字段。** 控件集合必须与现在完全一致。`tests/panel.test.js` 里那条控件清单快照会重新生成——**重新生成之前先确认集合确实没变**,变了就是错了,不是快照过期。
- **不改任何行为。** 点击、校验、保存、重渲染的时机一样。
- **不删 i18n 目录里的键。** 句子从按钮文字变成 tooltip,不是消失。
- **不引入依赖、不引入构建步骤。** 只用客户自带的 Font Awesome 和客户自带的折叠模式。
- **不新增构建期的东西。** 扩展仍然是被 ST 当静态站点加载的三个文件。

## 测试

- **控件清单快照重新生成**,并在同一个提交里说明「集合没变」这件事是怎么核对的（不是「快照更新过了」）。
- **孤儿图标键测试**:映射表里每一项都被用上。
- **每一个图标化过的按钮都带 `title` 与 `aria-label`,且两者都双语。** 遍历按钮断言这一条,不要只断言某一个。
- **非法尺寸值会展开它所在的尺寸集**（上面那条),以及改对之后可以收回。
- 折叠默认状态符合上面那张表。
- 折叠块用的是客户的 `inline-drawer-*` 类,不是自造的结构——**断言类名**,这样「别退回自造」是可测的。
- 仍然测不了的:图标是否真的画出来了、动画观感、悬停提示好不好看。留给手动验收。

## 已知取舍与偏差

- **图标化牺牲了可发现性,换取密度。** 文字按钮不用悬停就知道是什么,图标要悬停。这是这一票明确接受的代价——那一排按钮在窄栏里本来就要占三行,而它们是偶尔用的动作,不是主路径。`title` + `aria-label` 是补偿,但**补偿不等于等价**。
- **图标化不适用于标签。** 刻意只做动作按钮。一个界面上如果连字段名都是图标,用户就得靠记忆定位,所以这一条是硬边界:要动文案就说,别动标签。
- **折叠状态不持久化**,理由在上面。
- **这一票的「好不好用」仍然测不出来。** 和票 10 一样:390 个通过的测试能证明控件集合没变、结构对、无障碍属性在,但证明不了图标看得懂、折叠点得准。手动验收那条列表是唯一的兜底。

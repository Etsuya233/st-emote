## 一、按钮图标化

### 背景

截图里一排「Upload images / Add image URL / Export .zip / Delete pack」全是有字的按钮,占了三行竖直空间,却只传达四个动作。Font Awesome 已经在用了——`panelSkeleton()` 里就有 `fa-solid fa-circle-chevron-down`,客户自带字体,运行时不新增依赖。

### 做什么

- **动作按钮改成只有图标**,本地化的句子移进 `title` 与 `aria-label`。**i18n 目录里的键一个字都不删**,它们从按钮文字变成了 tooltip,仍然是双语。
- **哪些改成图标**:上传图片、加外链、导出 zip、删除表情包、替换表情图、删除表情、创建包、导入包、复制正则、试渲染、重新渲染、批量删除、创建缺失的表情包。
- **哪些保持文字**:所有**说明性标签**——下拉框的标题、尺寸字段的名字、复选框的说明、那一大段提示文字、以及「HTML tag form:」这种冒号前缀。这些是标签不是动作,图标化只会让用户看不懂。
- 图标名的映射表放在 `adapter/ui.js` 里,照抄现有 `PLACEMENT_LABEL_KEYS`（在 `sizing-panel.js`）与 `PACK_STATE_LABEL_KEYS` 的写法:**一张语义名 → 类名的表,不是散落各处的字符串**。
- `actionButton()` 的签名跟着改成接图标加标签,`filePickerButton()` 同样。
- 图标要有**尺寸与对齐**的统一规则（`style.css` 里一条 `.st-emote-button` 族）,不能每个按钮各写各的字号。

### 可发现性

图标化是**有代价的**:文字按钮自带标签,图标没有。三个必须做的补偿——

1. `title`（悬停提示,双语）
2. `aria-label`（读屏）
3. 面板顶部的「这段操作是什么」那一句提示里,说明按钮是图标且悬停有说明

**如果实机验证发现某个动作图标化后明显更难找**,那个按钮可以保留文字——但要在 Comments 里写明是哪一个、为什么。

### 图标不存在怎么办

FA 的图标是按名字查的,**查不到就是空白,没有报错**。所以:

- 图标名要挑 FA6 免费版确定有的,别用 Pro 独有的（`fa-file-zipper` 这类拿不准的先查一遍）
- 加一条**孤儿键测试**:图标映射表里的每一项都必须有人用,就像目录的孤儿键测试那样。这样删按钮时不会留下一个查不到名字的图标

### 手动验收项

- 每个图标都真的渲染出来了,**没有一个是空白**（这一条自动化测不了,只能看）
- 悬停提示在深色/浅色主题下都读得清
- 读屏能念出每个动作（`aria-label` 生效）

## 二、区块可折叠

### 用客户自己的模式,不要自造

`panelSkeleton()` 已经在用 SillyTavern 的 `inline-drawer-toggle` + `inline-drawer-content` + `inline-drawer-icon fa-solid fa-circle-chevron-down down`。**折叠块也用同一套**——客户自己的动画与样式白拿,面板看起来也是原生的。自造一套 `<details>` 或手写 max-height 动画是在重复发明一个我们已经用着的东西。

> **实施时更正了一处**:客户自己的委托**不写 `aria-expanded`**,它只做动画与 `fa-circle-chevron-*` / `down`↔`up` 的切换。所以这个属性得我们自己维护(见 Comments 的判断 4)。折叠的其余部分——盒子、动画、点击、键盘可达——确实都是白拿。

### 折叠哪些

| 区块 | 默认 | 理由 |
| --- | --- | --- |
| 两套**尺寸集**（`inline` / `block` 各一组 7 个字段） | **收起** | 一次 14 个输入框,是面板最大的一块。绝大多数用户不调 |
| **宏**说明 + 示例 | 收起 | 一段说明加一整块 `<pre>`,没有设置 |
| **正则**说明 + 示例 + 复制按钮 | 收起 | 同上 |
| **导入导出**说明 + 导入行 | 收起 | 偶尔用一次的操作 |
| **试渲染**（调试区） | 收起 | 是个工具,不是设置 |
| **处理**组（总开关 + 两个形态开关 + 用户消息） | **展开** | 这些是主开关,折叠起来等于藏起来 |
| **标记**组（标签名） | 展开 | 一个输入框,不值得折 |
| **投放方式** | 展开 | 一个下拉框 |

「外观」组里的尺寸集单独折,组本身不折——一个组折起来、组里两个子块各折一层,三层套娃比不折还难找。

### 折叠**不能藏住错误**（这条最容易漏）

非法尺寸值会在输入框旁边显示提示、在控制台记一行。**如果那一组是收起的,用户永远看不到那个提示。** 所以:

- 一个尺寸集里**有非法值时,自动展开**它,并保持展开直到那个值被改对或被清空
- 这条要有测试:存一个非法值 → 面板挂载 → 那一组是展开的;把值改合法 → 下一��重新渲染时它可以收回
- 同理,总开关关掉时那半句「宏也不展开」的提示不能被折叠挡住（它本来就在展开的组里,但要确认）

### 状态不持久化

折叠状态**只活在这次挂载里,刷新页面回到默认**。不要为此建一套持久化机制——没有人要求它,而持久化就要决定「存哪、怎么合并、和票 08 的 `settings` 什么关系」,那是一件单独的票。

有一个例外要注意:面板里**包列表**每次改动都会整体重建（`refresh()`）,但**设置区不会**。所以设置区的折叠状态天然能在编辑过程中保持,不需要额外做什么;而包列表那一侧的状态(见票 12)是另一回事,不要在这里顺手建。

### 手动验收项

- 折叠块的展开/收起动画与客户自己的抽屉一致
- 键盘可达:`tab` 能走到折叠头、`enter`/`space` 能展开、`aria-expanded` 正确
- 一个非法尺寸值在收起状态下被发现时,那一组是否真的自动展开了（这条有测试,但观感要人看）
- 收起的尺寸集,它的标题上**看得出里面被改过**吗（没改过的两套看起来一样,改过的应该认得出来）——如果做不了,在 Comments 里说明

> **实施时做了**:折叠头右侧挂一个「已改过」小标记（`size.customized`),任何字段非空就打上——两套默认都是七个空字段,所以收起的两套本来长得一模一样。非法值那一套会再多挂一个红标记,并说明它为什么自己展开了。**标记在窄栏里挤不挤仍然要人看。**

## 已知取舍与偏差

- **图标化牺牲了可发现性,换取密度。** 文字按钮不用悬停就知道是什么,图标要悬停。这是这一票明确接受的代价——那一排按钮在窄栏里本来就要占三行,而它们是偶尔用的动作,不是主路径。`title` + `aria-label` 是补偿,但**补偿不等于等价**。
- **图标化不适用于标签。** 刻意只做动作按钮。一个界面上如果连字段名都是图标,用户就得靠记忆定位,所以这一条是硬边界:要动文案就说,别动标签。
- **折叠状态不持久化**,理由在上面。
- **折叠块的顺序按使用频率排,不按功能分组。** 尺寸集 → 试渲染 → 宏 → 正则 → 导入导出。功能上后三个是同一类(都是「说明 + 一次性操作」),排在一起会更好读;按频率排则把最常动的放在最上面。选了频率,因为面板的用户来这里是为了改东西,不是为了读说明书。代价是同类的三个被频率拉开了,读起来没那么整。有一条测试把这个顺序钉住,否则它会静默地退化。
- **「这里有一个值不是尺寸」那句删掉了。** 它原本放在折叠头部,配 `white-space: nowrap`,一句 60 字符的话把整个头部撑到比面板还宽:标题被压成一列单词、chevron 被顶出可视区。句子是多余的——那一组本来就是**因为**这个值才自己展开的,展开之后那个字段旁边已经有提示了,再说一遍"我为你展开了"属于啰嗦。现在头部只有一个 `!`,句子在它的 tooltip 上。
- **这一票的「好不好用」仍然测不出来。** 和票 10 一样:通过的测试能证明控件集合没变、结构对、无障碍属性在,但证明不了图标看得懂、折叠点得准。手动验收那条列表是唯一的兜底。

### 判断题（可能需要人推翻）

1. **图标名的核对方式**:`tests/contract/font-awesome.js` 记下 `FREE_ICON_CLASSES` / `FREE_ICON_CODEPOINTS`——当初对着客户的 `public/css/fontawesome.min.css` **和** `public/webfonts/fa-solid-900.ttf`（读它的 cmap）逐个核过。**只查样式表不够**:客户那份 CSS 里带着若干 Pro 才画得出的类名,查样式表会放过去;字体里有没有那个 codepoint 才是决定的一半。版本号记成 6.5.2,因为免费集在 6.x 内会长大,换名字时要重新核而不是相信旧记录。孤儿键测试**两端都查**:表里每项都得有人画,画出来的每个类名都得在表里,面板上的按钮与键表**双向相等**（否则删掉一个按钮,孤儿那一半照样绿）。
2. **`st-emote-icon-button` 进了 `PRESENTATION_HOOKS`**,和 `st-emote-button` 同理:它说的是「怎么画」而不是「是什么」,挂在每个动作按钮上,不携带身份。正因如此,图标化 30 多个按钮**没有**把快照改写 30 多行——一屏全是同一个新增类的 diff,没人看得下去。
3. **删表情包（`fa-trash-can`）与批量删除（`fa-trash-arrow-up`）用了两个不同图形。** 票里允许某个动作保留文字,理由写在上面了;反过来,「两个都叫删除」共用一个桶也可以。我选了两个形状,**这一条我拿不准,得在实机上看并排时分不分得清**。
4. **`aria-expanded` 我们自己写。** 客户端的委托只做动画与 `fa-circle-chevron-*` 切换,**从不写这个属性**。我们的监听器跑在目标阶段（早于 document 上的委托),**且刻意不碰 `content.style.display`**——`slideToggle` 靠当时的可见性决定往哪边滑,我们先改了会让它滑反。理由写在 `collapsible.js` 的模块注释里。
5. **搜索框从 `.st-emote-import` 那一行里拆了出来**（票里的「导入行」只留导入按钮)。它过滤的是正下方的包列表,是「不打开任何东西就能用」的那一个,跟着导入说明一起折起来最不合理。
6. **图标化的硬边界只做动作。** 下拉框标题、字段名、复选框说明、那几段提示、「HTML tag form:」这种冒号前缀全部原样留字。这条写在 `EXPECTED_ICON_BUTTON_KEYS` 的注释里,以免下一个人重新决定一次。

### 真机上看出来的：「自动展开」把**填充方式**也当成了非法值

用户在真机面板上看到「Inline size」每次挂载都是展开的,头上挂着 `!`,提示是「needs a number with em, px or %」。查下来是本票那条规则的实现问错了问题:

- `SIZE_PANEL_FIELDS` 里有 `fit`,而它存的是 `cover` / `contain` / `fill`——**没有一个是长度**。「这一组是不是存了坏值」用 `validateSizeValue` 问遍整张表,于是**选过填充方式的每一组都被判成存了坏值**,每次挂载自己展开、头上挂 `!`,而 `!` 的句子在讲一个用户从没打过的数字。改法:`core/size.js` 加 `isUsableSizeField(field, value)`,`fit` 走 `validateFitMode`,其余走 `validateSizeValue`;头的句子也跟着字段走（填充方式被拒绝时用新增的 `size.invalidFitHint`）。
- 顺带查出**同一处的第二个错**:`buildFitField` 收的是 `stored.fit`（一个字符串）,函数体里又读成 `stored.fit`(即 `undefined`),所以**下拉永远显示 default**——渲染走的是存储里的 `contain`,面板却跟用户说自己没设过填充方式。JSDoc 把参数标成 `SizeSet` 是同一个错的另一半。参数改名成 `value`,类型改对。

**票 11 的自动展开规则本身不动**:一个真的存了坏值的尺寸集仍然自己展开,那正是本票要防的事(折叠藏住错误)。要改的是「什么算坏值」。这两条由 `tests/panel.test.js` 的「a 尺寸集 whose Fill was chosen is not a 尺寸集 holding a bad value」与 `tests/size.test.js` 的「every panel field is asked by its own rule」钉住——**第一版快照只记 select 的选项、不记选中值,所以下拉显示错值这一条当时测不出来**,新测试里加了对 `select.value` 的断言。

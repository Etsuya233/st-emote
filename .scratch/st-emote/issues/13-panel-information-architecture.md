# 13 — 面板的信息架构：主内容在前，设置折叠，状态可见

**What to build:** 面板现在是「一整面设置 + 最下面才是表情包列表」。用户打开面板先读十来行散文、拨四五个开关，最想去的表情包列表压在最后。改成四块：状态条 → 表情包（主内容，带搜索与新建）→ 渲染 → 外观 / 接入与工具。主内容提到最上面并自己滚动，设置各块给真标题，首屏散文砍到两行，状态条随时回答「现在到底生效的是什么」。

**Blocked by:** 11 — 面板交互：图标化按钮，可折叠的区块

**Status:** resolved

> **接在票 11 的「留给后续 Ticket」最后一条**：票 11 明确记下了「表情包列表仍然排在整块设置之后……要不要动是独立的决定，牵涉的是『面板是设置页还是数据页』」。本票就是那个决定：**它是数据页**，设置是附带的。
>
> 票 12（表情网格）会在同一个 `tests/panel.test.js` 的控件清单上动手。**两张票串行做，不要并行开 worktree。**

## 背景

票 10 立了「两档间距 + 一条细线」的分块约定，票 11 折了五处。两条都成立，但合起来留下一件事没解决：

- **主内容在屏幕外。** 包列表排在所有设置之后，前面是约 40 行控件。`common_dev.md` 里票 11 自己的注释说顺序「按被触及的频率排」，而加表情包恰恰是最高频的动作。
- **权重完全一致。** 总开关、用户消息开关、两个形态开关在 DOM 上只差一个类；唯一的提示是 `opacity: 0.8` 的「Token forms」小字，它不像标题，像又一个 label。
- **首屏被文档占满。** `panel.intro` + `panel.iconHint`（3 行，讲的是「按钮是图标」这件 UI 事实）+ `panel.enabledHint`（4 行）+ `panel.sizeHint`（4 行，且错位——它讲 em/px/%，却紧挨着总开关）。约 11 行，占首屏四成。
- **唯一那个创建入口最没有存在感。** 一个只有 placeholder 的输入框加一个 `+`，和搜索框之间隔着四个折叠段。placeholder 一输入就消失，看起来像预填内容。
- **没有状态读数。** 「我现在启用了哪些包」「模型能用哪些标签」在面板上要靠数复选框才看得出来。

## 做什么

### 一、四块，主内容在前

```
st-emote                                2 packs · 14 stickers   [抽屉头，可折叠时也看得见]
──────────────────────────────────────────────
● Active here · 2 packs · 14 stickers            ← 状态条
   (关掉时整条变成 ○ Rendering is off — …)
──────────────────────────────────────────────
PACKS                                      3        ← 主内容
   [ 没有表情包时：一张上手卡片，四步 + 按钮说明 ]
   [🔍 搜索标签与描述……………………………]
   [ New pack name ][__________][ + ]          ← 与搜索同属工具栏
   ┌ 滚动区（max-height）────────────────┐
   │ 表情包卡片                            │
   └──────────────────────────────────┘
──────────────────────────────────────────────
RENDERING
   ┌ 总开关（自己的样式：整行、1em、粗）┐
   │ ☑ Render stickers at all         ⓘ  │
   └──────────────────────────────────┘
     （说明只在关掉时上屏，句子常驻 title）
   ☐ Render stickers in user messages
   TOKEN FORMS
   ☑ Bracket form   ☑ HTML tag form
     ␣ HTML tag form: [sticker]           ← 缩进一级，看得出属于上面那个勾
──────────────────────────────────────────────
APPEARANCE
   （em/px/% 那段说明在这里，而不是挨着总开关）
   Placement [In place ▾]
   ▸ Inline size [changed]
   ▸ Block size
──────────────────────────────────────────────
SETUP AND TOOLS
   ▸ Try rendering / re-render
   ▸ Listing macro
   ▸ Context-clearing regex
   ▸ Import and export a pack
```

**包列表自己滚动**（`max-height` + `overflow-y`），搜索框与新建行留在滚动区外面。这样无论有多少个包，下面的设置都还在伸手可及的地方。

### 二、块标题是允许的（推翻票 10 的一条）

`common_dev.md` 写着「分块用间距和细线，不用卡片……加块标题要在中英两份目录里同时加句子，所以除非确实说不清，一律用间距解决」。

本票的判断是：**这里确实说不清**。段内 6px / 段间 12px 只差 6px，而分块线画的是 `var(--SmartThemeBorderColor)`——深色主题下这个变量本身就很暗，截图里那三条线基本等于不存在。四十个控件里没有落点，不是间距不够的问题。

所以给四个块各一个真标题：字号更小、字重更高、字距略宽、**大写**（中文下自然不变形），opacity 0.6。代价是四个键，收益是眼睛有六个落点而不是四十个。

**间距与细线两档约定本身不动**——标题是加在上面的，不是替代它们的。

### 三、首屏散文砍到两行

- `panel.intro` 压到一句。
- `panel.iconHint` 从首屏**移进上手卡片**（只在还没有表情包时出现）。它讲的是「按钮长什么样」这件 UI 事实，对老用户是纯噪音。
- `panel.enabledHint` 变成总开关那一行的 `title`（常驻可悬停），**可见文字只在开关关掉时出现**。为一个还没发生的后果写四行字是浪费，而真关掉时它恰好是最该被看见的一行。
- `panel.sizeHint` 从总开关下面**搬进 APPEARANCE 块**。它讲 em/px/%，放在总开关旁边本来就是错位的；同一句话再挂成块标题的 `title`。
- 上手卡片（仅在库为空时）四步：起名 → 上传并填标签 → 在作用域启用 → 预设里写 `{{st-emote}}`。最后一步是最容易漏的一步——不写宏，模型永远不知道有哪些标签可用。

### 四、状态条与抽屉头

- 抽屉头右侧常驻一个读数（面板收起时也看得见）：`2 packs · 14 stickers`，关掉时是 `off`。
- 抽屉内容第一行是状态条：`● Active here · 2 packs · 14 stickers`；总开关关掉时整条变成 `○ Rendering is off — stickers on screen are back to their markers`。
- 数字来自 `effectiveSetForMessage(context, -1)`——与宏清单、调试区预览**同一个**生效集，所以三处永远说同一件事。
- 生效集里有**冲突**时，状态条下面多一行 `conflict.header`（复用现成的键与 `.one`）。这是「我启用了、也上传了、为什么不渲染」最常见的一个原因。

### 五、新建那一行

给它一个**看得见的标签**（复用 `panel.newPackName`，同时仍是 placeholder），输入框与 `+` 并排，和搜索框同属表情包块的工具栏。仍然是图标按钮——票 11 的硬边界（动作图标化、标签留字）不动。

## 测试

- **控件清单快照一个字不改**，并且**不改就该过**。这是本票最有分量的那一条：它证明这次动的全是版式，一个控件都没增删改名。
- 抽屉里第一个块是表情包块，包列表排在总开关之前。
- 状态条的数字跟着作用域勾选走；总开关关掉时整条换一句话。
- 抽屉头的读数与状态条一致。
- 上手卡片只在库为空时出现，且中英各说各的话。
- 四个块都有标题，标题句子在两种语言里都存在。
- `.st-emote-packs` 真的有 `max-height` 与 `overflow`（用 `readStyleSheet()` 断言，jsdom 没有排版引擎，这是唯一能验的形状）。

**要改的既有断言**（都是有意改的，不是被迫改的）：

- 「总开关的后果写在开关上」那条：改成先断言开着时那行**不在屏上**，再关掉后断言它在。原因还是那句话——为一个还没发生的后果占四行是本票要治的病。
- `i18n` 的孤儿键表补上新键。

## 手动验收项

- 四块的标题在窄栏（~300px）与宽栏里读起来是不是「四个东西」而不是「一栏控件」
- 包列表自己滚动之后，滚到列表底部会不会把整个面板一起带着滚（`overscroll-behavior`）
- 抽屉收起时头上那行读数读不读得清
- 上手卡片四步在 300px 栏里挤不挤
- 总开关关掉时状态条换句话这件事，眼睛会不会注意到

## 已知取舍

- **嵌套滚动是有代价的。** 列表自己滚之后，外层抽屉的滚动条和内层列表的滚动条同时存在，滚到列表尽头要再滚一次才出得来。选它是因为「设置被推走」比「多滚一次」严重得多。
- **总开关的说明不再常驻。** 老用户可能不知道那句话写了什么，tooltip 兜着，代价是「关掉之后才知道原来有这句说明」。
- **上手卡片是一次性的。** 有了第一个表情包它就消失，而那正是最需要它的时刻之后。

## 已知取舍与偏差

- **试渲染不是逐字节等于聊天**。渲染规则走的是同一条（`renderHtml`），但 markdown 那一步用的是**我们自己配的** showdown 转换器：客户不公开它自己的配置，我们只开了 spec 解析边界点名的围栏与表格两项。所以预览是「很接近」而不是「可证相同」，面板的提示里写明了这一点，而不是让用户自己发现。
- **没有 showdown 就按纯文本处理**，并且在控制台说明当时用的是哪一种。`escapeText` 不只安全，也是诚实的下限：它同时是「调试框不会因为粘进来的 `<img onerror=…>` 变成一个漏洞」这条保证的原因——预览的 HTML 是本扩展**唯一**一处写进面板的渲染标记。
- **预览用最终的类名 `custom-st-emote`**，不是钩子路径那个不带前缀的 `st-emote`：预览的 HTML 是原样插进面板的，没有任何净化器会替它补前缀，用钩子路径的名字会得到一张尺寸正确但完全没有样式的图。
- **`rerenderChat` 必须在两条路径上都跑**，而 DOM pass 只在一条上跑——这条分界写在 `rerenderChat` 自己的注释里，并且由 `tests/hook-path.test.js` 盯着。再把它合成一个门，下一个读代码的人就会以为「钩子路径上不需要重绘」。
- **测试需要 `npm install`**（dev 依赖 `jsdom`），扩展本身没有构建步骤、不依赖它；`core/` 仍然不依赖 ST 也不依赖 DOM。

# st-emote — 需求规格

Status: ready-for-agent

术语见 `CONTEXT.md`（本规格全文使用其中的词），关键取舍见 ADR-0001 ～ ADR-0004。

## Problem Statement

角色扮演里"发一张表情"这件事现在只能靠文字描述或让模型生成图片：

- 内置的 Character Expressions 是**角色立绘**，位置在聊天窗旁，不是消息里的表情，而且由情感分类器决定，用户无法让它"在回复的某个位置发一张自己准备的表情包图片"
- 社区里的同类插件要么只解决"用户自己手动贴一张"（选择器 + 正则），要么把语法写死在代码里、标签不可配、也不区分作用域
- 用户没法控制"这些表情只在全局可用 / 只在某个角色可用 / 只在某个聊天里可用"
- 想复用自己的表情包，得手工维护图片链接和一条条正则，改一个名字就要全局替换

结果是：用户想要的那种"模型在最合适的位置发一张我准备的表情包"目前只能靠一堆正则和 URL 拼出来，难维护、易失效、跨设备就散。

## Solution

做一个 SillyTavern 扩展，把这件事拆成两个各自独立、都由用户掌控的部分：

1. **表情侧**：用户把本地图片（或图片外链）上传进**表情包**，给每张**表情**填一个短**标签**和一段**描述**。启用哪些表情包，由**全局 / 角色 / 聊天**三层**作用域**分别决定，生效集是它们的并集。
2. **提示词侧**：扩展注册一个宏 `{{st-emote}}`，用户在**自己的预设里**写下它，拿到当前可用表情的**清单**（一行一个 `表情包名:标签`）。扩展**从不修改提示词**。用户自己决定在预设里怎么指示模型写标记。
3. **渲染侧**：模型写出 `[[sticker:表情包名:标签]]`（或 `<sticker>表情包名:标签</sticker>`），扩展把标记替换成图片——出现在原地、段后或消息末尾，尺寸与填充方式可配。未命中的标记从显示中消失并记控制台。

## Implementation Decisions

### 模块与测试缝

计划中的缝只有**一条**：**纯核心 ↔ ST 适配层**。

- **纯核心**（不依赖 ST、不依赖 DOM，可直接用 node 测）：标记解析、生效集解析、清单生成、渲染拼装（把"输入数据 + 一段 HTML"变成"输出 HTML"）、尺寸配置求值
- **ST 适配层**（薄，不放规则）：从扩展设置 / 角色卡 / 聊天元数据读数据并组装成核心的输入；把核心输出接上 ST 的消息格式化钩子或 DOM 后处理；上传、i18n、设置面板；两条渲染路径的差异只允许存在于"把结果送进 DOM"这一步

选这条缝的理由：所有行为规则都落在纯核心，测试不需要浏览器；适配层只做搬运，行为一致性由共享的断言辅助覆盖。

### 领域模型（不变量）

1. 一个**表情** = 一张图片 + 一个标签 + 一个描述
2. 一个表情**只属于一个表情包**；一张图片只被一个表情使用（不允许共享引用）
3. 一个表情**只有一个标签**；标签是表情的属性，不是多对多的标记关系
4. 一个表情包的**名字全应用唯一**，并充当标记里的限定名（没有独立的命名空间字段）
5. 同一个表情包内**不允许两张表情同名**（编辑 / 上传时拦截）
6. 作用域只持有一组「已启用的表情包」，不持有标签
7. **没有标签的表情**（刚上传、还没填）不进清单、不参与匹配，管理界面标为「待填标签」

### 标记语法

两种形态：

| 形态 | 写法 |
| --- | --- |
| 标记式（默认） | `[[sticker:表情包名:标签]]` |
| HTML Tag 式 | `<sticker>表情包名:标签</sticker>`（标签名可配置，默认 `sticker`） |

**为什么只能是这两种形态**（防止后来者"简化"成社区常见写法）：

- `:shortcode:` 不能用作标记：ST 的 Markdown 转换开着 emoji 扩展，已知 shortcode 会在我们处理之前就被换成真 emoji（标签名叫 `smile` 就永远匹配不到）
- 裸 HTML 标签（`<sticker:happy>`）不能作默认形态：它的落地形态取决于用户的 `encode_tags` 设置（默认关闭、可打开），开时被转义、关时原样透传，行为不可预期
- `[[...]]` 在两种设置下都稳定，也不会被 Markdown 解析成链接或图片

解析规则：

- 按**第一个 `:`** 切分：前半是表情包名，后半是标签
- **生效集只含一个表情包**时，`[[sticker:标签]]`（省略前缀）也能解析；此时带前缀的写法同样有效
- 生效集含多个表情包时，裸标签一律算**未命中**
- 同一条消息里同一个标记出现多次 → **每次都插**
- HTML Tag 式必须同时匹配转义与非转义两种落地形态（`<sticker>x</sticker>` 与 `&lt;sticker&gt;x&lt;/sticker&gt;`）
- HTML Tag 式的标签名不得与真实 HTML 标签同名（校验并拒绝 `p / div / span / br / img / code / pre` 等）
- 标签比较：`trim` → 折叠内部空白 → 大小写不敏感；存储保留用户原文

字段约束：

| 字段 | 上限 | 字符约束 |
| --- | --- | --- |
| 标签 | 32 码点 | 禁 `[` `]` `<` `>` 与换行；允许 `:` 与 emoji |
| 表情包名 | 32 码点 | 同上，且禁止 `:`（按第一个 `:` 切分需要） |
| 描述 | 1000 码点 | 只能单行；**可为空**（纯管理信息，界面里空描述显示为「—」） |

重命名（包名或标签）会让此前写好的标记失效：操作时给出明确提示。已渲染的旧消息不受影响，但下次重渲染时按未命中处理。

### 生效集与作用域

- 三层作用域，每层持有一组「已启用的表情包」：全局（扩展设置）、角色（写进角色卡）、聊天（写进聊天元数据）
- **生效集 = 各层启用表情包的并集**，按包去重。**纯并集**：只能加不能减，没有排除、没有覆盖、没有优先级
- 一个表情包可以同时被多个作用域启用（多对多）
- 新建 / 导入的表情包默认不启用
- 群聊里，角色层按该条消息的作者所属角色卡解析
- 角色卡引用了本地没有的包 → 显示「缺失的包」提示，可一键导入
- 缺图的包：界面标灰、仍可启用，点一下是「重新指定图片」入口
- 包名全应用唯一：创建 / 改名时撞名直接拦截（不自动加后缀）

### 渲染

- **两条路径**（ADR-0002）：ST ≥ 1.19.0 用官方消息格式化钩子（`afterMarkdown`，DOMPurify 之前）；1.15.0–1.18.x 用 DOM 后处理
- **两条路径产出相同的类名** `custom-st-emote`：钩子路径写 `class="st-emote"`（ST 净化消息内容时统一加 `custom-` 前缀），DOM 路径由我们手动添加；行为标识一律用 `data-*` 属性；CSS 只写一份
- 时机：流式生成实时渲染（标记写完整即出图）；设置变更（改标签 / 改包名 / 启停 / 尺寸 / 关开关）立即重渲染当前聊天；半截标记保持原样，写完整后出图
- 处理范围：AI 输出处理；用户消息默认不处理（有开关）；系统 / 旁白不处理；思考链不处理；超过 ST 楼层显示上限、未被渲染的消息自然不处理
- 未命中（标签不存在 / 包未启用 / 图片缺失 / 外链失效）→ 从显示中移除该标记，并写控制台；生效集为空时所有标记都是未命中
- DOM 路径必须幂等：重渲染、Show more、swipe、编辑消息后不得重复插入

### 投放方式与尺寸

投放方式：原地 / 块后 / 消息末尾。全局默认 + 逐表情覆盖；覆盖投放方式等于同时切换尺寸配置套。块后 = 当前段与下一段之间，边界按块级容器取（段落 / 列表项 / 引用块 / 标题 / 表格单元），断行不算块。

尺寸两套（`inline` / `block`）：原地用 inline 套，块后与消息末尾用 block 套。每套 = `min-width` / `min-height` / `max-width` / `max-height` + 填充方式 `cover` / `contain` / `fill`。

- 单位 `em` / `px` / `%` 手打，**值原样交给 CSS**；非法值视为未设置并在输入框旁可见提示
- **默认值**：inline 默认 `max-height: 3em`、其余留空；block 默认 `max-width: 100%`、其余留空
- `%` 只在宽度方向承诺有意义（CSS 里高度的 `%` 依赖父元素高度，不承诺）
- inline 套建议按文字高度配置，界面明示「1em = 当前聊天文字高度」
- block 语境下多张图：每张各占一个块，竖排

### 提示词：宏

- 注册宏 `{{st-emote}}`，**只输出清单数据，不输出任何指令 / 脚手架文本**
- 档位走参数：`{{st-emote}}`（默认，等同 `::full`）、`{{st-emote::simple}}`（只列标签）、`{{st-emote::full}}`（每行 `表情包名:标签`）
- 清单行格式：一行一个 `表情包名:标签`；描述不进入提示词
- 生效集为空 → 展开成一个「无」字
- 展开时机：每次构建提示词时实时计算
- 语言跟随 ST 界面语言（中英双语）
- **扩展绝不修改 / 注入用户提示词**（ADR-0004）
- 另提供一条**只清上下文**的正则规则，以可复制的 JSON 形式交付：`promptOnly: true`（绝不清显示端）、作用于 AI 输出、同时匹配两种标记形态、开启 `runOnEdit`；不自动注入正则扩展

### 存储

- 形态（ADR-0003）：图片写入 ST 用户数据目录下的既有特性目录，经 ST 自带的上传接口写入；元数据在扩展设置；角色层在角色卡；聊天层在聊天元数据
- 跨设备（同一 ST 服务端）可见；不随角色卡导出图片；同一个包可跨角色复用
- 删除单张表情 / 删除整个包：立刻删图（删包二次确认）
- 允许外链（图片不落盘），界面标注「外链」
- 包导出 = 一个压缩包，内含图片文件 + 一份元数据 JSON（每个表情的标签、描述、图片文件名，以及该表情的投放方式覆盖）
- 包导入：包名已存在 → 拒绝并提示（不自动改名、不覆盖）；导入后默认不启用
- 图片格式 `png` / `jpg` / `webp` / `gif`（动图原样保留、不改帧）；单文件 ≤ 5MB，超出报错；不自动压缩，上传时提示建议尺寸（高度 ≤ 512px）

### 管理界面

设置面板含：表情包与表情管理、作用域启停、投放与尺寸配置、宏用法示例、缺失包提示。上传在某个表情包内点击、一次多选、自动归属该包，标签与描述逐张填。表情条目操作：改标签、改描述、替换图片、调整投放方式覆盖、删除，并支持多选 + 批量删除。描述用于界面展示与搜索。包列表用第一个表情的缩略图当封面、按名字排序。另有斜杠命令（启停某作用域的包 / 重载 / 查冲突）与调试区（「重新渲染当前聊天」按钮 + 「试渲染」输入框）。界面与宏输出中英双语，跟随 ST 语言设置。

### 日志

未命中、冲突、非法尺寸等只写浏览器控制台（统一前缀），不做界面日志面板。

### 兼容

地板 **1.15.0**，写进扩展清单的 `minimum_client_version`；低于地板的版本 ST 会拒绝加载，扩展无需自行判断。1.15.0–1.18.x 走 DOM 后处理，≥ 1.19.0 走官方钩子（两版的宏系统、`getContext`、`writeExtensionField`、`getRequestHeaders` 均已具备）。

### 解析边界

1. 代码块与行内代码里的标记不渲染
2. 引用块、列表项、表格单元里的标记照常渲染
3. 开场白（第一楼）里的标记照常渲染
4. 用户消息默认不处理（有开关）
5. 系统 / 旁白消息不处理
6. 思考链不处理
7. 超过 ST 楼层显示上限、未被渲染的消息不处理
8. 生成中半截的标记保持原样，写完整后出图
9. 标签比较大小写不敏感、忽略多余空白；存储保留原文
10. 空包（一个表情都没有）允许存在，列表里显示为「空」

## Testing Decisions

- **什么算好测试**：只测外部行为——纯核心测"给定输入数据与一段消息 HTML，输出什么 HTML / 清单文本"；不测内部函数调用顺序、不测私有结构。两条渲染路径的差异属于实现细节，只断言"最终 DOM 里出现同样的结构、同样的类名、同样的尺寸样式"
- **被测模块**：纯核心（标记解析、生效集解析、清单生成、渲染拼装、尺寸求值）是主要测试对象，覆盖全部规则与边界（两种标记形态、转义与非转义、单包裸标签、多包裸标签、重复标记、代码块跳过、未命中的四种来源、空生效集、撞名、非法尺寸值、`::simple` / `::full` / 无参数）
- **不被测的部分**：ST 适配层的搬运逻辑、上传与设置面板的交互，靠手动在 ST 里验收；DOM 路径需要一个 DOM 环境来断言最终结构
- **既有范式**：本仓库目前没有代码，测试是第一批，没有可继承的既有范式；缝按上面的"纯核心 ↔ ST 适配层"建立
- 测试夹具用**真实的 ST 渲染产物**（showdown 输出）作为输入，而不是手写的简化 HTML，避免测出"只在我们想象的结构里成立"的规则

## Out of Scope

- 不做情感分类、不自动挑表情（那是内置 Character Expressions 的职责）
- 不做图片生成
- 不做触发词匹配：没有字面量匹配、没有正则标签，只有标记
- 不复用官方 Sprites 接口（ADR-0001）
- 不修改、不注入用户提示词（ADR-0004）
- 不做单张表情的临时停用
- 不接受 SVG 上传；不自动压缩图片
- 不新增服务端代码
- 不做界面日志面板
- 不做"某个作用域排除某个包"的减法语义

# 双渲染路径，且两条路径产出同一个类名

ST 1.19.0 才提供官方消息格式化钩子（`afterMarkdown`，DOMPurify 之前），而本扩展要支持 1.15.0 起的版本，所以保留 DOM 后处理作为旧版路径。代价是两条路径产出的 DOM 必须手工保持一致：类名统一为 `custom-st-emote`（钩子路径写 `class="st-emote"`，由 ST 净化消息内容时统一加上 `custom-` 前缀；DOM 路径由我们自己添加），行为标识一律用 `data-*` 属性，CSS 只写一份。

**Consequences**：不写这条约定，后来者会把那个"多余的 `custom-` 前缀"当成 bug 修掉，从而静默破坏旧版本；新增任何视觉属性时都要同时照顾两条路径。DOM 路径还必须幂等（重渲染、Show more、swipe、编辑消息都不能重复插入）。

## 追加：块级修饰类（票 04）

`custom-st-emote` 是**每一张**表情图都要带的基类，投放方式为块后 / 消息末尾的图在此之上**追加**修饰类 `custom-st-emote-block`（钩子路径写 `st-emote st-emote-block`，净化后同样得到 `custom-` 前缀的两个类）。也就是说基类永远在场，修饰类只做加法。

**为什么**：`img.custom-st-emote` 是 DOM 路径挑选表情图的唯一入口（投放方式重定位、加载失败清理都靠它）。如果块级图只带修饰类而丢掉基类，选择器就再也匹配不到它们，块级投放方式会在旧版路径上静默失效，而且失效的表现是"图还在、就是不动"，很难归因。投放方式本身是**行为**，由 `data-st-emote-placement` 表达，类名只表达**呈现**——这与本 ADR 一贯的"行为标识一律用 `data-*`"是同一条规矩。

**Consequences**：不要把 `-block` 当成基类的替代写法；也不要把 `max-height` 这类只对某一套尺寸集成立的属性放回基类 CSS 里（块级图也会带基类），否则它会顺着基类漏到块级图上。尺寸一律由图片上的内联 `style` 承担，基类只留两种投放方式都成立的兜底值。

# 双渲染路径，且两条路径产出同一个类名

ST 1.19.0 才提供官方消息格式化钩子（`afterMarkdown`，DOMPurify 之前），而本扩展要支持 1.15.0 起的版本，所以保留 DOM 后处理作为旧版路径。代价是两条路径产出的 DOM 必须手工保持一致：类名统一为 `custom-st-emote`（钩子路径写 `class="st-emote"`，由 ST 净化消息内容时统一加上 `custom-` 前缀；DOM 路径由我们自己添加），行为标识一律用 `data-*` 属性，CSS 只写一份。

**Consequences**：不写这条约定，后来者会把那个"多余的 `custom-` 前缀"当成 bug 修掉，从而静默破坏旧版本；新增任何视觉属性时都要同时照顾两条路径。DOM 路径还必须幂等（重渲染、Show more、swipe、编辑消息都不能重复插入）。
